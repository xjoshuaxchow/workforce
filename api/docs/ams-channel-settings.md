# AMS 通訊設定與三語電話操作

本批功能為獨立 Workforce，不接 Core、不新增工種。業務語言保留英語、粵語、普通話，電話內容可選本機完整 MP3、Azure 完整 MP3、Twilio Say 或自備 MP3／WAV 片段。本機合成只支援粵語及英語。

## 管理員入口

登入 http://127.0.0.1:5210，左側選「通訊設定」。只有 admin 可進入；site_manager 可管理有權限 Site 的調度。

### 連線設定

- Twilio：模式、Account SID、Auth Token、主叫號碼、公開 HTTPS 回調網址前綴。
- WhatsApp：模式、既有 microservice origin、API key。origin 不加 /v1。
- Token／key 是寫入欄位。保存後留白顯示「已設定」，不將原值回傳瀏覽器，留空保存會保留原密鑰。
- 保存即成為新版本，新邀請使用新設定。舊 Attempt、原調度跟進通知和既有 Call SID 沿用其帳號、服務網址、主叫號碼及內容快照；同一 Twilio 帳號或同一 WhatsApp 服務 origin 更換憑證後，使用最新保存的 Token／key，不再接受已撤銷舊 Token 的簽章；原 mock 待發工作不會因啟用真實模式而變成真實發送。
- 畫面會確認從 mock 啟用真實渠道。存取舊頁面、另一管理員已保存新版本時，寫入回409；重新整理後再操作。

原 .env 是首次建立設定的 bootstrap。資料庫已有設定後，以 AMS 保存版本為準；修改 .env 供應商欄位不會覆寫已保存版本。

### WhatsApp 模板

1. 選內容語言：英語／粵語／普通話，及通知用途：邀請、確認、額滿、取消、班表發布、班表變更。
2. 儲存服務 URL／key 後可「讀取微服務模板」。清單跟隨服務分頁，顯示 Meta 核准狀態。
3. 可建立、修改或確認刪除純文字 BODY 模板，邀請帶兩個 quick-reply 按鈕。名稱、語言、文字、位置變數範例送到既有微服務，再由 Meta 審核，保存不等於已核准。
4. 選「使用此模板」或填模板名稱與 Meta 語言 code，設定 BODY 位置變數的對應與接受／拒絕按鈕 index。內容語言與 Meta code 分開，例如粵語內部是 yue，Meta 模板可能為 zh_HK。
5. 按「儲存設定」。真實 service 模式需完成三語的六種用途映射。發送前再向微服務核對模板 APPROVED、名稱／語言、位置變數及按鈕形狀，未符合不 POST messages。

不支援的複合模板元件／named parameters 不會作為此 POC 的可用模板；這批不搬入健身房聊天 package 或會員、提醒與廣播頁。

### 電話語音

先在員工資料選擇語言，再於「電話語音 → 電話內容方式」選擇方案。儲存只影響新發出工作，舊調度與跟進通知保留原方案及內容。

#### 本機生成完整 MP3

1. 本機環境已安裝 VITS Cantonese 與 Piper 英文。其他後端先執行 `python3 scripts/install-local-tts.py`，使用私有環境及校驗過的模型；重跑可核對並重用已存檔。這台 Mac 完整環境約306 MB，模型與英語音素資料約196 MB，其餘為執行套件。
2. 選「本機生成完整 MP3（粵語／英語）」，確認顯示已安裝，選語速並儲存。毋須 Azure Key。固定字句在「AI MP3 固定講稿」編輯，動態資料及按鍵鎖定。
3. 調度草稿加入合資格員工後，核對完整講稿，按「生成缺少 MP3（語言）」。粵語繁體字由後端轉成模型可讀形式，日期、時間、樓層及按鍵數字會作口語轉換；`28/F` 讀成二十八樓，`G/F` 讀成地下，其他斜線讀成斜線。時間依 Site 時區計算，本機語音不朗讀 GMT／UTC 偏移。姓名使用通用稱呼；每工作、語言及用途保存完整 MP3，共用提示跨工作重用。
4. 生成後可直接試聽，音檔齊備才可發佈。某一段不滿意，可在該段按「修改這段講稿」，只改固定字句；地點、日期時間、補充說明及按鍵保持自動填入。按「儲存並只生成這段」後試聽，其他滿意的 MP3 保留；「只儲存講稿」則稍後再按該段「生成此 MP3」。修改只影響這份工作，不改全域設定或其他工作。已修改的段落可按「恢復預設講稿」，如原錄音仍適用便直接重用。已發工作不能再修改講稿，跟進及 DTMF 使用原播放快照，無 Say 或 Azure 後備。
5. 失敗可重新生成，不會出現 Azure 計費確認。不支援字元會列出具體字元供修改，原始程序記錄不回傳瀏覽器。後端同時只運行一個本機生成程序，其他操作提示稍後重試；單段最多60秒，逾時或超過3 MB請縮短講稿。程序完成或終止後清理臨時檔案。
6. 粵語講稿中的英文詞組會交給 Piper 整組朗讀，例如 `tech nine`，再與 VITS 粵語保存為同一個完整 MP3。中英切換時聲線會不同。`28/F` 仍讀成二十八樓。
7. 英文地點可在「工作地點 → 編輯地點」填「英文朗讀名稱」及「英文朗讀地址」，只影響英文 MP3。原名稱及地址已是英文時可留空；中文補充說明仍需另改成英文，系統不會自動翻譯或略過。缺少英文資料時，對應音檔會顯示待補欄位。
8. 草稿「試聽語言」可選「英語試聽」或「粵語試聽」，生成後直接播放。試聽不會修改員工語言或發電話；發送仍按合資格員工語言檢查所需 MP3，發送後只顯示已固定的工作音檔。生僻地名及多音字仍須試聽，必要時修改固定用詞。普通話員工在本機模式會阻擋發佈，系統不會擅自更改員工語言。

模型來源與套件版本保存在 `.local/onnx-tts/UPSTREAM.json`，英文模型附上游 `MODEL_CARD`。粵語轉換模型上游未明確標示權重商用授權，本功能不作商用授權聲明。正式公司使用前需確認權重及資料集條款。

測試沒有發出真實電話。兩語已用真實本機引擎生成完整 MP3，透過 API 保存、取回及重用，並以 fake Twilio 驗證發佈後的 Play；外部 ngrok 音檔存取與實際電話音質仍需通話驗收。

#### Azure 生成完整 MP3

1. 可先用私人 Azure 帳戶建立 Speech 資源，選 F0 免費層測試，取得 Key 及 Region。設定方式見 [Microsoft 說明](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/get-started-text-to-speech)。目前官方 F0 定價為每月50萬計費字元的 Neural 額度，詳見 [官方收費](https://azure.microsoft.com/en-us/pricing/details/speech/)。中文的計費字元換算以 [服務說明](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/text-to-speech) 為準。
2. 在「電話內容方式」選「Azure 生成完整 MP3」。輸入 Azure Speech Key 及資源的 Region 代碼，例如 eastasia。選粵語／英文／普通話聲線，按「儲存設定」。Key 留空保留，儲存後不顯示原值。只有這次儲存不會生成音檔或撥電話。
3. 可在同頁「AI MP3 固定講稿」編輯固定用詞，通用稱呼及資料佔位維持鎖定。英文預設 Hello there，中文／粵語用同事作稱呼，整個工作不加入個別員工姓名。
4. 到調度草稿「調度電話語音」，核對完整邀請、確認、取消及回覆提示的文字。包括 Site 名稱地址、當地開始及結束完整日期時間、UTC 時差、補充說明與按鍵。按「生成此 MP3」，或按「生成缺少 MP3（語言）」依序生成。後者只處理尚未生成或明確失敗的項目。生成使用 Azure 額度或產生合成費，試聽不撥電話。
5. 每份音檔生成後可直接試聽。同工作、同語言及同用途的完整 MP3 供所有電話重用。收妥、無輸入及額滿提示按相同文字／聲線跨工作共用。重複操作直接取得已保存音檔，並發請求不會再次提交。
6. 連線中斷、5xx 或檔案接收不完整時顯示結果未確定，不自動重試。重新整理／檢查只讀狀態，不重新合成。若要再次生成，按「重新生成此 MP3…」並確認可能再次收費。生成中斷超過90秒也會顯示此狀態。401／403等明確拒絕可在修正 Key／Region／額度後重新按生成。
7. 所有需要的語言及跟進檔都齊全後才可發佈。發佈保存整套播放快照，Twilio 僅 Play 完整檔案、收 DTMF1／2／9，無 Say 後備。沒有 Azure 設定仍可看文字；不能生成缺檔工作。WhatsApp-only 草稿只生成可能用於電話後備的用途。

公司確認後建立公司的 Speech 資源，把 AMS Key 和 Region 換成公司資料再儲存。既有 MP3 保存在 Workforce，更換這兩項不要求重新生成；改聲線、固定講稿、地點資料或工作內容則新草稿須用新檔，已發工作保留原檔。生成中的成功回應也能在設定被另一管理員更換後保存。

本功能尚未填入實際 Azure Key，真人讀音、特殊地名及電話音質仍需實際試聽驗收。Azure 介面採 [官方 REST 協定](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/rest-text-to-speech)，輸出16kHz mono MP3；測試使用假 Azure 回應，不能代表聲音品質。

#### 自備錄音

1. 選「自備 MP3／WAV 片段」，選錄音語言、分類及片段。按畫面的建議內容錄音，或配對已上傳的同語言錄音。每檔上限 3 MB；WAV 需 PCM 16-bit。
2. 共用提示包括通用稱呼的邀請／確認／取消開場、開始／結束連接詞、按鍵1／2／9、收妥、無輸入及額滿提示。年份錄0至9數字，中文另錄「年」；月／日／小時／分鐘片段包含畫面標示的單位。小時採24小時制，00分使用「正」或 o'clock。
3. 時差只需準備會使用的 UTC 偏移。Site 錄音須包含名稱和地址；名稱、地址、時區變動後重新配對。其他已保存片段仍保留。完成配對按「儲存設定」。不必先錄齊所有日期及時差。
4. 建立草稿、加入員工後，在「調度電話語音」看各語言欠缺清單。非空補充說明需另上傳該語言的錄音。改動共用設定後按「重新檢查錄音」。
5. 選邀請、確認、取消或額滿通知，可逐段或連續試聽。試聽不撥電話。缺漏時禁止發佈並保留草稿。WhatsApp-only 草稿亦顯示電話後備檢查，不需要未使用的邀請／補充錄音。

播放順序為開場、地點地址、開始完整日期時間及時差、結束完整日期時間及時差、補充錄音與按鍵。通用稱呼不讀員工姓名。兩邊日期都讀出，英語日期順序為日、月、年份數字。建議統一語速、音量並裁去多餘靜音；片段依序播放，可能有短暫停頓，沒有自動語音合成後備。

發佈會保存各語言及通知用途的完整播放計劃。後續設定修改、Site 地址變更、音檔封存均不修改該工作內容。自備錄音使用 [Twilio Play](https://www.twilio.com/docs/voice/twiml/play)，並在 [Gather](https://www.twilio.com/docs/voice/twiml/gather) 內收取按鍵。公開 HTTPS 網域需同時提供 `/media/voice/…`，正式反向代理亦要轉送 `/media`；本機 Vite 已包含此代理。實際真人錄音品質與外部 Twilio 播放仍須真機確認。

#### Twilio Say

選 Say 時顯示三語聲線：

| 員工語言 | Twilio language | Twilio voice |
| --- | --- | --- |
| 粵語 yue | yue-HK | Google.yue-HK-Standard-A |
| 普通話 zh | cmn-CN | Google.cmn-CN-Standard-A |
| 英語 en | en-GB | Google.en-GB-Standard-A |

新邀請自動讀出員工姓名、Site 名稱與地址、按 Site 時區換算的完整開始／結束日期和時間，以及調度額外訊息。跨午夜時讀出結束日期，時區偏移亦在內容內。接受按 1、拒絕按 2、重聽按 9。無效按鍵重播；沒有按鍵則播放無輸入提示並結束。確認、取消及無法接單通知使用同一語言。

Say 模式不需要錄音或另外建立 TwiML App。舊電話若已保存錄音快照，仍播放原音檔。發送前保存員工語言，該調度後續通知沿用；之後更改員工語言只影響新調度。

聲線依據 [Twilio 官方清單](https://www.twilio.com/docs/voice/twiml/say/text-speech)。程式指定 voice 和 language，不依賴 Console 的預設聲線。真機仍須核對地址、數字及日期讀音。

### 編輯固定講稿

在「通訊設定 → 電話語音」選擇講稿語言及用途。修改「固定字句」文字框，再按頁頂「儲存設定」。可修改邀請與按鍵提示、確認、取消、收妥、無輸入及額滿／無法接單內容。用詞不自然或多音字讀錯時，可改用較口語的寫法或同音字。

綠色標籤是系統填入的員工姓名、地點與地址、開始／結束日期時間及補充說明。接受1、拒絕2、重聽9亦鎖定，不能在文字框刪除、替換或更改按鍵作用。文字預覽將這些資料標成佔位標籤，真實電話會加入該次調度的值。文字當成純文字朗讀，不執行HTML或SSML。

每段最多400字，每份講稿固定字句合計最多1200字，不能全部留白。三語及各用途分別保存；儲存未改其他語言或用途。已發出的邀請及其確認／取消等跟進沿用原設定版本，新邀請才使用新講稿。儲存講稿不會重新發送任何電話；文字預覽不會撥號。實際音質與讀音仍以Twilio試撥為準。

### 本機公開回調

1. 啟動 API 8310 與 AMS 5210。
2. 執行 `ngrok http 8310`。
3. 在「公開回調網址前綴」填 ngrok 的 HTTPS 網域，例如 `https://example.ngrok-free.app`。不加 `/api` 或 DTMF 路徑。
4. 保存 `twilio-pstn` 設定。新邀請自動產生 `/integrations/twilio/voice/<attempt-id>/twiml`、`/gather`、`/status` 的完整 URL。
5. 以自己的測試電話建立單人直接邀請，核對語言及 9／1／2 回覆。接受後，原通話結束才撥接單確認電話。

測試期間保持 API 與 ngrok 運行。網址變更時，先更新 AMS 再建立新邀請。已提交電話仍依賴原網址。Twilio 帳戶需有目的地撥號權限，試用帳戶亦需符合接收號碼限制。

## 加密金鑰與啟動

新設定以 AES-256-GCM 加密存在 messaging_settings_versions。可用32-byte base64 的 WORKFORCE_SETTINGS_KEY；本機未提供時，首次建立 api/.local/settings.key，權限600，資料夾不進Git。既有資料庫的 key 遺失時啟動會停止，不自動建立替代 key。

備份時保留資料庫與原 settings.key；換機或還原亦要一起還原。不需要把 Twilio／WhatsApp key 貼到聊天、放進前端 VITE_* 或提交 Git。

```sh
cd /Users/joshua/ns-workforce-api
nvm use
npm ci
npm run db:migrate
npm run dev
```

AMS 另在 /Users/joshua/ns-workforce-ams 執行 npm run dev。本機預設仍 mock；真實試撥／試發另需有效憑證、已批准模板、可接收測試號碼及公開 HTTPS 回調／音檔網址。

## 驗證界限

自動化以 workforce_test、fake Twilio／fake HTTP 驗證設定、版本保護、映射、Say TwiML、DTMF、歷史音檔與表單。沒有真實電話、Meta 模板建立或 WhatsApp 發送。真機仍需核對音質、語言、班次內容、公開網址、接聽與送達。
